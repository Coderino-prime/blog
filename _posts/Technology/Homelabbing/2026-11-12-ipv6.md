# I had my reverse proxy...

...but all of my services were set up as simply as possible.
Namely, they all used *IPv4* for routing.
IPv4 has a problem, though: there aren't enough addresses!
The solution is IPv6; a vastly wider address scheme that's generally easier to configure.
It follows a colon-delineated format with eight, four-character sections.
These are alphanumeric characters, with lowercase & capital letters being equal, and *including* 0.
For example: `0abc:1def:2ghi:3jkl:4mno:5pqr:6stu:7vwx` is a valid IPv6 address!

I call out 0 specifically because, in IPv4, 0 acts as a sort of wildcard character.
It's a stand-in for any other number, allowing you to write IP based firewall rules that can match swathes of IPs.
For example: `192.168.1.0/24` matches any IP from `192.168.1.1` to `192.168.1.255` (the `/24` states how many bits it should look for).
With IPv6, you simply don't write the part you want to wildcard.
For example: `0abc:1def::6stu:7vwx/64` wildcards the `2ghi:3jkl:4mno:5pqr` bit in the previous example.

When you want to connect to an IPv4 address directly and need to specify the port you're connecting to, you do `1.2.3.4:8080` or similar.
This might a problem for IPv6, which uses colons for delineation.
Simply wrap the IP in angle brackets: `[0abc:1def:2ghi:3jkl:4mno:5pqr:6stu:7vwx]:8080`!

IPv6 has been in the process of being adopted worldwide for a while now, and I decided I wanted to contribute (even if the reason is "just because").
The first step is ensuring my router even supported IPv6.
Most do, but often have it disabled by default to avoid confusion in less technical users.
Once it's enabled, your router will receive an IPv6 from your internet service provider and start publishing IPv6 addresses to devices on your LAN.

I, however, have been containerizing my applications using Podman which has IPv6 disabled by default.
It's a simple enough change; just adding `--ipv6` to any network creation command enables it.
If you use `podman compose`, just `ipv6: true` in the network block works.
After recomposing my containers to enable IPv6, many worked out of the box.
Caddy, for example, didn't really mind the change.
Others, like Jellyfin, required some additional in-app configuration.
This was usually, as in Jellyfin's case, just enabling an IPv6 support option in the settings.

After I tested through everything with local addresses, I needed to set up Porkbun.
IPv4 uses an A(*ddress*) record to link a domain name to a machine address.
IPv6 uses a AAAA record (coloquially "quad-A") to do the same thing.
Setting up Porkbun is about as easy as one would expect.
I simply set my public IPv6 as a AAAA record and all my CNAME records I had already for IPv4 now also point to the AAAA record.
As an aside, though I've never verified as such, I choose to believe that's a tongue-in-cheek name as IPv6 uses four times the bits as IPv4.
If my time working with software has taught me anything, it's that the nerds love a cheeky naming convention.

While I initially wanted to drop IPv4 in it's entirety, IPv6 isn't globally adopted yet.
That, unfortunately, included some of my friends who played on my Minecraft server[.](/assets/img/EasterEggs/Chopper.png)
For the time being, my IPv4 support would continue so everyone could play as normal.
Removing IPv4 support is something I might try again in a couple years, but for now I can live with it.

Having all the IPv6 support felt great!
I was backing a new global standard, and I learned some new stuff about networking.
There was a new problem I had introduced, though.
IPv6 addresses are *long*, so typing it by hand each time to remote onto my server was annoying.
I could still use the IPv4 address to connect, but that felt out of the spirit of the work I'd just done.
So I started researching how to set up my own, localized domain names...
